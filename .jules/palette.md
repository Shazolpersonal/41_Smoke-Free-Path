## 2024-05-06 - Missing Keyboard Dismissal and Input Accessibility
**Learning:** Found a recurring UX/accessibility anti-pattern where text inputs lack `accessibilityLabel`/`accessibilityHint` and are housed inside `ScrollView`s without `keyboardShouldPersistTaps="handled"`. This leaves screen readers silent on bare inputs and frustrates users who cannot easily dismiss the mobile keyboard by tapping outside.
**Action:** When adding or reviewing `TextInput`s, especially outside of generic `FormInput` wrappers, always verify they have explicit accessibility labels and ensure parent scroll views handle taps to dismiss the keyboard properly.

## 2024-09-03 - Smooth Searchable List UX with Keyboard Dismissal
**Learning:** Found an accessibility/UX issue in screens with persistent search bars above list views (like Library and Dua screens). Even when a parent view attempts to handle keyboard taps, long scrolling `FlatList` components need explicit keyboard properties to feel native. Without `keyboardDismissMode="on-drag"`, users cannot intuitively drag down to dismiss the keyboard, and without `keyboardShouldPersistTaps="handled"`, tapping list items while the keyboard is open might just close the keyboard instead of registering the tap.
**Action:** When implementing searchable lists with sticky search headers and `FlatList` or `ScrollView`, always pair `keyboardShouldPersistTaps="handled"` with `keyboardDismissMode="on-drag"` on the main list, and add `keyboardShouldPersistTaps="handled"` to any adjacent horizontal scrollable tab selectors to ensure interactions remain responsive while the keyboard is open.
