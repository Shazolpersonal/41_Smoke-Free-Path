## 2024-05-06 - Missing Keyboard Dismissal and Input Accessibility
**Learning:** Found a recurring UX/accessibility anti-pattern where text inputs lack `accessibilityLabel`/`accessibilityHint` and are housed inside `ScrollView`s without `keyboardShouldPersistTaps="handled"`. This leaves screen readers silent on bare inputs and frustrates users who cannot easily dismiss the mobile keyboard by tapping outside.
**Action:** When adding or reviewing `TextInput`s, especially outside of generic `FormInput` wrappers, always verify they have explicit accessibility labels and ensure parent scroll views handle taps to dismiss the keyboard properly.

## 2024-05-24 - Provide Screen Reader Hints for Disabled Actions
**Learning:** In the `smoke-free-path` React Native app, several key interactive components (like `<TouchableOpacity>` and `<Pressable>`) manage their `disabled` state via style opacity and functional checks rather than the built-in React Native `disabled` prop in some cases, or they omit accessibility attributes when disabled. Consequently, screen readers may not announce that the button is disabled or explain *why* it is disabled, leading to confusing user experiences for visually impaired users.
**Action:** When a button or pressable card is functionally disabled (e.g., waiting for valid form input, unselected trigger, or future steps), always supply `accessibilityRole="button"`, `accessibilityState={{ disabled: true }}`, and critically, an `accessibilityHint` that explains the requirement to unlock the action (e.g., "পরবর্তী ধাপে যেতে সব তথ্য পূরণ করুন").
